# Implementation Plan: CursachPD — Recommendations Engine

## Summary

Spring Boot 3.x application implementing a recommendations engine with static and dynamic rules, accessible via REST API and Telegram Bot. Layered architecture (controller/service/repository/engine), Spring Data JPA with H2/PostgreSQL, Caffeine cache, SpringDoc OpenAPI.

---

## Phase 1: Project Setup

### 1.1 Update `pom.xml`
**File:** `src/main/java/org/example/` — replace placeholder Main.java

Dependencies: Spring Boot 3.2.5 (web, data-jpa, cache, validation), H2 (runtime), PostgreSQL (runtime), telegrambots-spring-boot-starter 6.9.7.1, springdoc-openapi-starter-webmvc-ui 2.5.0, caffeine, spring-boot-starter-test, maven-checkstyle-plugin.

### 1.2 Create `checkstyle.xml`
**File:** `checkstyle.xml` — Google-style rules for static analysis (NFR-05).

### 1.3 Create application configuration
- `src/main/resources/application.yml` — main config (server.port=8080, telegram bot token, cache TTL)
- `src/main/resources/application-dev.yml` — H2 in-memory DB, H2 console enabled
- `src/main/resources/application-prod.yml` — PostgreSQL via env vars (DB_HOST, DB_PORT, DB_NAME, DB_USERNAME, DB_PASSWORD)

### 1.4 Create main application class
**File:** `src/main/java/org/example/cursachpd/CursachPdApplication.java` — @SpringBootApplication, @EnableCaching, @EnableScheduling

### 1.5 Delete placeholder
Remove `src/main/java/org/example/Main.java`

---

## Phase 5: Static Rules Engine

**File:** `engine/StaticRuleEngine.java`

Embedded rules (cannot be modified at runtime):
1. Category-based filtering — if user likes "X", recommend items tagged "X"
2. Time-based rule — different content based on time of day
3. Frequency-based rule — don't repeat the same recommendation too often
4. Popularity-based rule — include trending items

---

## Phase 6: Dynamic Rules Engine

**File:** `engine/DynamicRuleEngine.java`

Loads active rules from DB, evaluates in priority order against user categories. Condition is JSON expression.

---

## Phase 7: Recommendation Engine

**File:** `engine/RecommendationEngine.java`

Orchestrates static + dynamic rule evaluation, generates recommendations, saves to DB, updates statistics.

---

## Phase 9: REST Controllers

| Controller | Endpoint | Actor |
|------------|----------|-------|
| RecommendationController | `POST /api/recommendations` | User (US-01) |
| RuleController | `POST/PUT/DELETE /api/rules`, `GET /api/rules`, `GET /api/rules/active` | Manager (US-03..06) |
| StatisticsController | `GET /api/statistics` | Manager (US-07) |
| CacheController | `POST /api/cache/clear`, `GET /api/cache/info` | External System (US-08, US-09) |

All controllers annotated with SpringDoc @Tag, @Operation for Swagger.
